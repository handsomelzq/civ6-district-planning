## 这个项目想证明什么

不是"我做了一个像文明 6 的游戏"，而是：

> **我把文明 6 的产出规则精确还原到可对账的程度，并在其上做了关卡设计与数值标定。**

所以这个仓库里最值得读的不是玩法，是**规则是怎么被查实的**，以及**查错之后文档是怎么被改的**。

## 怎么跑

全部工具**只用 Python 标准库**（系统 `python3` 3.9 即可，不需要建 venv、不需要 pip install）。

```bash
python3 Tools/check_config.py              # 配置表一致性校验（21 条规则）
python3 Tools/test_check_config.py         # 校验器自己的回归测试（66 条断言）
python3 Tools/analyze_yields.py            # 产出量级分析（数值设计.md 的数字来源）
python3 Tools/design_levels.py             # 重算关卡目标值与星级阈值，重新生成关卡表
python3 Tools/motif_check.py               # 关卡母题验证（先校准，校准不过就停）
```

求值器与网页（TypeScript）。也是零依赖 —— **Node 24 原生跑 TypeScript**，测试用内置 `node:test`，构建用内置的 `module.stripTypeScriptTypes`：

```bash
npm test                                   # 44 条测试：校准 / 不变量 / 交叉校验 / 关卡阈值
node Tools/build_web.mjs                   # 构建网页（把 .ts 剥成 .js，配置表内联）
node Tools/serve.mjs                       # http://localhost:8123/web/
```

构建完之后 **`web/index.html` 双击就能打开**——配置表是构建期内联的，不依赖任何服务器。

需要装了文明 6 才能跑的：

```bash
python3 Tools/parse_civ6_xml.py            # 游戏 XML → 配置表 CSV
```

**可复现性是这套工具的硬指标**：删掉 `配置表/*.csv` 再跑一次 `parse_civ6_xml.py`，13 张生成表逐字节一致。

## 这个项目的工作方式（三条自己给自己立的规矩）

### 1. 数值只能来自一手数据

所有数字来自游戏本体的 XML，或**游戏内实测**。二手资料（wiki、攻略）可以临时占位，但必须标 `待核=是`，而 `check_config.py --delivery` 会**拦住任何 `待核=是` 的行**进入对外产物。

理由不是洁癖：拆解过程中二手资料至少有两处与一手数据冲突（军事篇的受损惩罚曲线；"文明 6 没有负向相邻"这句话本身就是错的——韩国书院就是）。

### 2. 判据必须可计算，而且必须真的拿去跑

文档里写"最优布局结构性改变"是一句愿望，写"交叉代入双向劣化 ≥ 0"才是判据。这个项目里有两条验证指标**被实测逼着从愿望改成了判据**，记录在 [设计/GDD总纲.md](设计/GDD总纲.md) §6.1。

> **指标一旦真的拿去跑，就会暴露它到底可不可计算。**

### 3. 错了就改文档，并把"为什么会错"留在原处

这个项目删掉了两个原本写好的关卡母题（A「争格」、D「取整浪费」），都保留了原节作为记录——因为它们各自记下了一次真实的方法论失误：一次是判据不够严导致的假阳性，一次是建立在未验证机制上的设计整块作废。

同类记录还有：把 L-06 做不出来归因为"地图太小"（错的，见 [设计/关卡设计.md](设计/关卡设计.md) §4.1；真正原因是我的协同块形状不对，几何搜索证明这张图有 14 万种可行摆法）；把圣地的建筑高算倍数手算成 3.7 倍（实际 4.1~5.0 倍）。

## 已知的空缺（写在明面上）

- **军事整块阻塞**：`units.csv` / `combat_modifiers.csv` 未生成，母题 F（地形与支援的取舍）无法设计。阻塞项是两条需要游戏内实测的规则：多个大将军是否叠加、受损惩罚曲线
- **`districts.OnePerCity` / `MaxPerPlayer` 未补**：所以 [设计/数值设计.md](设计/数值设计.md) §1 的相邻上界是「忽略全局唯一性」的上界
- **预算 6+ 的关卡做不了**：穷举最优在预算 6 以上吃不住，需要束搜索求解器（在暂缓清单里）
- **多产出关卡的难度度量不够好**：`V−G`（合计差）在多维目标上失真，见 [设计/数值设计.md](设计/数值设计.md) §4.1
- **自由模式未做「导出关卡草稿」**：两个模式本身已上线（见顶部试玩链接），缺的是把自由模式摆出来的局面导出成 `levels.csv` 一行，见 [设计/SDD-自由模式.md](设计/SDD-自由模式.md) §3.5
- **边界 F1–F8 未逐条走查**：求值器侧的边界（E 系列）已测，模式层的 F 系列还没
- **没有类型检查**：Node 的 TypeScript 支持是「类型剥离」，只去掉类型不检查类型。要真查需要装 `typescript` 跑 `tsc --noEmit` —— 这是唯一一个值得加的开发依赖，目前刻意还没加
- **🔴 `自身` 类别的语义未经实测**（SDD §10 D10）：全库唯一一条是韩国书院的 +4 科技。两种读法——「无条件固定 +4」与「挨着另一座书院才 +4」——都已实现并测过，开关是 `evaluate.ts` 的 `SELF_IS_FIXED_VALUE`，当前取前者。**这不是个小细节**：若实测取后者，L-09 的三星阈值从 20 变成 0，且「韩国关卡结构性地不可能让贪心失败」这条结论会整个反过来。先验证据是提示文本（103 条相邻规则里 102 条点明产出来源，只有这条不点明），已由 `check_config.py` 规则 21 守住

## 本机怎么跑解析脚本

解析脚本需要装了文明 6 的机器。它按 `$CIV6_ASSETS` → 各平台 Steam / Epic 默认位置的顺序找游戏目录：

```bash
python3 Tools/parse_civ6_xml.py                      # 自动找
CIV6_ASSETS=/path/to/Assets python3 Tools/parse_civ6_xml.py   # 手动指定
```

**可复现性是硬指标**：删掉 `配置表/*.csv` 再跑一次，13 张生成表逐字节一致。
