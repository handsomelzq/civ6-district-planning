# 阶段验收

读[项目约定](../../../AGENTS.md)、[制作管理](../../../studio/roles/producer.md)及[测试视角](../../../studio/roles/qa-tester.md)。

1. 明确待验收目标：继续开发、内部试玩、作品集展示或完整交付。没有目标时先作现状评估，不擅自推进阶段。
2. 检查对应设计、任务验收条件、代码及最新测试证据；文档存在不等于内容合格。
3. 日常内部迭代可用 smoke 模式。展示/交付评估运行 node Tools/studio_check.mjs --mode gate，读取各项结果。
4. 严格交付检查可能因军事缺表、待核行等失败。完整交付据此 FAIL；若明确只评估区域规划子集，逐项标明不适用原因与范围，不绕过原始检查。
5. 对 README 的关卡唯一性/旧阈值缺口逐项查当前数据和验证逻辑；自动测试通过不等于所有关卡合法可玩。
6. 核对涉及 UI 的实际试玩证据、构建与受测版本是否一致、资源来源说明及交付范围；未测试写 NOT RUN。
7. 给出 PASS（本目标证据齐全）、CONCERNS（可继续但有明确缺口）或 FAIL（关键条件不满足），逐项指向证据和解决动作。

结果记录在 production 下，继续沿用 task_plan.md 的专项状态。只有实际满足条件才更新阶段。
验收不触发部署、PR、提交或对外上传。不要求多位虚拟总监签字，不伪造独立审查。
