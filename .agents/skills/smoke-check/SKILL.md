# 日常检查

读[项目约定](../../../AGENTS.md)和[测试视角](../../../studio/roles/qa-tester.md)。
本任务从父目录启动时，先定位到区域规划demo 再运行命令。

1. 读取本次变更范围和 git status，确认哪些失败在接入/修改前已经存在。
2. 执行 node Tools/studio_check.mjs --mode smoke；等待完成，读取退出码与输出报告。
3. 报告覆盖技能引用、Node 测试、开发模式配置校验、校验器回归、文档链接、Web 构建、包语法及差异空白检查。
4. 审阅警告和失败，不能把退出码 0 等同“没有问题”。配置缺表与待核等信息必须保留。
5. 若任务包含 UI 变更，启动已有本地预览并用可用浏览器工具执行相关路径：进入模式、放置、非法提示、收益明细、研究解锁或重置。
6. 浏览器/游戏内实测无法执行时记 NOT RUN；这不能充当 UI 验收通过。需要留存的截图使用实际捕获结果。
7. 输出报告路径、自动结果、试玩结果和剩余问题。测试请求本身不授权修改现有玩法。

检查脚本会重建 web/dist 并新增 production/qa 报告，不修改 CSV。
