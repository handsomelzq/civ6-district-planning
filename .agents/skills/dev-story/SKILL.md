# 实现已批准任务

读[项目约定](../../../AGENTS.md)、[模块导航](../../../studio/project-context.md)和[玩法程序视角](../../../studio/roles/gameplay-programmer.md)。

1. 任务可以是用户明确指令或具体任务卡；没有上游 Story/TR/ADR 文件不阻塞。用户只要求分析或诊断时不实施。
2. 读取验收条件、相关设计/配置/代码及现有 git diff。记录已有问题，保护未提交改动。
3. 说明将改哪些文件、为什么；重要配置、设计或架构变更遵守用户审核约定，已有明确批准不重复确认。
4. 实现范围内变化。逻辑放 src、表现放 web；数值走配置管线；共享落位规则维持单一实现。
5. 为新增或修复的关键行为补适当测试；对纯文案/低风险可逆变化不强造测试。对 UI 另做实际交互验证。
6. 运行相关测试并按需使用 smoke-check；遇到基线失败区分旧问题和本次回归，不为了通过而弱化断言。
7. 给出变化、验收证据、未验证项。任务卡确已满足验收才标 Done；不自动提交、推送或发布。

需要记录需求时用[任务卡模板](../../../studio/templates/story.md)；模板本身不授权新功能。
角色是检查视角，默认由当前 Codex 完成；不假设 Claude Task 存在。
