# 玩法与关卡探索

读[项目上下文](../../../studio/project-context.md)、[游戏策划视角](../../../studio/roles/game-designer.md)，再读相关 GDD/关卡设计章节。

1. 从用户本次想解决的体验问题开始，例如读不懂相邻收益、研究解锁缺少反馈或布局取舍不足。
2. 给出二至三个确有差异的方案，分别说明玩家动作、决策取舍、反馈、适用场景、成本和最大不确定性。
3. 用具体小盘面说明规则如何产生体验；数值来源不明确时标为假设，不改写成文明 VI 的已确认规则。
4. 用户选择后，把方案收敛成最小验证：局面、操作、成功标准、需要哪些代码/美术/数据，以及一次试玩怎样判断有效。
5. 探索结果默认是提案。用户要求留档时存入 production 下的任务草稿；修改正式 GDD 前展示差异并依据已有授权处理。

尊重现有产品范围，不自动把区域规划扩展成完整 4X、联机或大地图模拟。
