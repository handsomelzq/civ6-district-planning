# 单系统设计

读[项目约定](../../../AGENTS.md)、[上下文](../../../studio/project-context.md)及[系统策划视角](../../../studio/roles/systems-designer.md)。

1. 明确本次系统与目标文件。已有 SDD 优先续写/审查，缺上游 systems-index 不构成阻碍。
2. 读取相关拆解、CSV 字段、SDD、代码和测试，区分原游戏机制、本 Demo 简化、待核项和新提案。
3. 覆盖实际需要的内容：目标体验、玩家动作、状态/规则、公式、边界、依赖、可调参数、UI 反馈与验收条件。
4. 公式写清输入单位、计数对象、替换与叠加顺序、舍入方式；用最小局面列期望贡献和总值。
5. 核对配置字段、求值器、落位判断、研究解锁与界面是否使用一致语义；列出会受影响的上下游。
6. 重要原文改动先给具体草案；获得批准后只改对应章节。保留历史错误记录及未验证标签，不为补模板重写整份策划案。

最终给出规则到实现/测试的对应关系。缺游戏实测时标明缺口，不伪造验收记录。
