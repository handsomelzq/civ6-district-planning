## 3. 已核对的风云变幻覆盖

### 3.1 资料片覆盖

- 使用 `Expansion2` 规则集，而不是只读取基础版或 `Expansion1`。
- 对同名 XML 按 `.modinfo` 的 `UpdateDatabase` 与 `ActionCriteria` 决定是否载入，避免 `Expansion1_Districts.xml` 的旧版本覆盖风云变幻版本。
- 支持 `Row`、`Delete`、`Update`、`Replace`、`InsertOrIgnore`，并处理 `Where / Set` 的属性形式与子元素形式。
- 对 `Types` 删除及外键 `ON DELETE CASCADE` 进行重放，确保风云变幻对基础数据的替换不是简单追加。

### 3.2 区域与相邻规则

- 工业区矿山相邻加成采用风云变幻的减半规则；旧的 `Mine_Production` 挂接被删除，不能继续按基础版 +1/格处理。
- 剧院广场相邻世界奇观的产出采用风云变幻覆盖后的最终值。
- 韩国书院的 `BaseDistrict_Science`、`NegativeDistrict_Science` 和市政广场相邻规则均保留。
- 俄罗斯拉夫拉的相邻规则按最终数据读取，不沿特色区域替换关系自行推导。
- 日本明治维新作为文明修正单独读取，并排除被其替换的通用标准档，避免重复计算。
- 德国汉萨及路德维希二世的相邻效果分别按文明和领袖来源记录。

### 3.3 研究系统

- 科技前置关系来自 `TechnologyPrereqs`。
- 市政前置关系来自 `CivicPrereqs`。
- 区域、建筑和精选政策卡的解锁内容由当前 `Districts`、`Buildings`、`Policies` 数据反向生成。
- 当前树的横向位置按前置图层计算，不再把时代当作硬性列约束；时代只保留为节点上的标签。

## 4. 仍然不是 XML 能直接给出的内容

以下项目不能因为 XML 对账通过就宣称已经完全还原：

1. 军事单位战斗力叠加、多个大将军是否叠加、受损惩罚曲线；
2. 区域配额的取整方式；
3. `Self` 类别的实际运行语义；
4. 负产出是否在最终 UI 层截断；
5. 世界奇观是否计入“任意其他区域”的具体边界；
6. 回合制科技值 / 文化值累积与研究时间。

这些项目继续保留在测试清单和 SDD 的待核区，不由网页布局或静态 XML 解析代替实测。
