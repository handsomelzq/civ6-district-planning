# SDD · 区域合法性系统

> 系统设计规格 ｜ 2026-10-03 方案版  
> 本文只定义区域放置与关卡初始局面的合法性边界，不修改人口配额、资源冲突或奇观占地规则。  
> 目标是让 UI 放置、求值器诊断和关卡加载使用同一套可追溯语义。

## 1. 设计目标

区域合法性系统需要同时满足四个目标：

1. 玩家能知道某个区域为什么不能放置。
2. UI、求值器、关卡加载不会各自维护一套互相分叉的规则。
3. 非法局面可以被诊断，但不会被静默当作合法局面。
4. 每条合法性规则都能追溯到配置字段、实现位置和自动测试。

本阶段的合法性范围：

```text
地块级约束
  → 城市级约束
  → 玩家级约束
  → 研究级约束
  → 模式级约束
```

本阶段明确不纳入：

- 人口决定的专业化区域总量公式；
- 资源是否允许被区域覆盖；
- 自然奇观 / 世界奇观的完整占地冲突；
- 建筑科技、市政、前置建筑和替换建筑的完整建造校验。

这些规则在证据和接口准备好后单独进入后续阶段，不能在本阶段用推断值混入关卡修复。

## 2. 合法性分层

### 2.1 地块级约束

地块级约束只依赖目标地块及其相邻地块，不依赖区域总数或挑战预算。

| 规则 | 数据来源 | 错误码 |
|---|---|---|
| 目标地块存在 | `BoardState.tiles` | `E00` |
| 目标地块没有已有区域 | `Tile.区域` | `E01` |
| 全局地形允许建区域 | `terrains.csv/是否可建区域` | `E02` |
| 区域自身地形限制 | `districts.csv/可建地形` | `E03` |
| 地貌允许建区域 | `features.csv/是否可建区域` | `E04` |
| 不可紧邻城市中心 | `districts.csv/不可紧邻城市中心` | `E05` |
| 水渠 / 浴场同时邻接城市中心与淡水 | `districts.csv/是否引水渠类` | `E06` |

建造区域时，如果地貌属于 `features.csv/是否需移除=是`，由 `withDistrict()` 在写入新局面时移除；这不是合法性失败。

### 2.2 城市级约束

| 规则 | 数据 / 状态 | 错误码 |
|---|---|---|
| 区域位于所选城市 3 格工作范围内 | `City.中心`、六边距离 | `E16` |
| 每城同类区域不超过配置上限 | `districts.csv/每城上限` | `E17c` |

没有显式多城状态的旧局面继续按单城处理。多城局面按区域的 `所属城市` 计数；相邻加成允许跨城市计算。

### 2.3 玩家级约束

| 规则 | 数据 / 状态 | 错误码 |
|---|---|---|
| 全局同类区域不超过玩家上限 | `districts.csv/每玩家上限` | `E17b` |

替换关系先解析，再按有效区域 id 计数。例如韩国局面中的基础学院按书院计数。

### 2.4 研究级约束

| 规则 | 数据 / 状态 | 错误码 |
|---|---|---|
| 区域前置科技已解锁 | `districts.csv/前置科技`、`BoardState.已解锁科技` | `E14t` |
| 区域前置市政已解锁 | `districts.csv/前置市政`、`BoardState.已解锁市政` | `E14c` |

研究状态只影响区域是否可放置，不改变当前已放置区域的区域侧相邻产出。

### 2.5 模式级约束

模式级约束只由交互模式提供，不能进入基础局面合法性。

| 规则 | 适用模式 | 错误码 |
|---|---|---|
| 挑战模式剩余放置预算大于 0 | 挑战模式 | `G5` |
| 挑战模式初始区域不可拆除 | 挑战模式移除操作 | `G4` |

`evaluate()` 不检查挑战预算；它只诊断局面本身。挑战 UI 在放置前把模式级问题加入统一结果。

## 3. 统一结果模型

新增 `src/legality.ts`，输出结构化问题，而不是让调用方解析中文文案。

```ts
export type LegalityLayer =
  | "地块" | "城市" | "玩家" | "研究" | "模式";

export type LegalitySeverity = "错误" | "警告";

export type LegalityIssue = {
  readonly code: string;
  readonly layer: LegalityLayer;
  readonly severity: LegalitySeverity;
  readonly message: string;
  readonly position?: Axial;
  readonly districtId?: string;
  readonly cityId?: string;
};

export type PlacementContext = {
  readonly mode?: "自由" | "挑战";
  readonly selectedCityId?: string;
  readonly challengeBudgetRemaining?: number;
  readonly protectInitialDistricts?: ReadonlySet<string>;
};

export function validateDistrictPlacement(
  rules: Rules,
  board: BoardState,
  position: Axial,
  districtId: string,
  context?: PlacementContext,
): LegalityIssue[];

export function validateBoard(
  rules: Rules,
  board: BoardState,
): LegalityIssue[];
```

### 3.1 结果顺序

问题按以下稳定顺序产生：

1. `E00` 目标地块不存在；
2. `E01` 已有区域；
3. `E02` 全局地形不可建；
4. `E03` 区域专属地形不匹配；
5. `E04` 地貌不可建；
6. `E05` 不可紧邻城市中心；
7. `E06` 水渠 / 浴场条件不满足；
8. `E16` 超出工作范围；
9. `E14t` / `E14c` 研究前置不足；
10. `E17c` 每城上限；
11. `E17b` 每玩家上限；
12. `G5` 挑战预算不足。

一个放置预览可以返回多个问题，但 UI 默认展示第一个阻断问题；科技和市政缺口可以合并成一条研究弹窗。

### 3.2 与现有函数的关系

现有 `districtPlacementConstraint()` 保留为地块级兼容函数，返回空字符串或首个地块级原因。

迁移后：

- `validateDistrictPlacement()` 是新的完整入口；
- `districtPlacementConstraint()` 只负责复用地块级逻辑；
- `withDistrict()` 仍是不可变数据构造函数，不主动校验；
- 任何正式交互、关卡加载和导出流程必须先调用合法性入口。

## 4. 调用方职责

### 4.1 Web UI

`web/app.ts` 在区域预览、点击放置和禁用层生成时调用 `validateDistrictPlacement()`。

UI 不再自行重复计算：

- 研究前置；
- 每城上限；
- 每玩家上限；
- 工作范围。

这样“置灰原因”和“点击时原因”来自同一结果。

### 4.2 求值器

`src/evaluate.ts` 对完整局面调用 `validateBoard()`。

要求：

- 非法局面保留产出树；
- 同时记录所有合法性错误；
- 不静默丢弃区域；
- 不检查挑战预算；
- 不把非法诊断降级为警告以迁就关卡数据。

### 4.3 关卡加载

`web/levels.ts` 加载关卡后立即调用 `validateBoard()`。

如果存在错误：

- 将关卡加入问题清单；
- 关卡标记为不可开始；
- UI 仍显示具体原因；
- `startLevel()` 拒绝进入该关卡。

当前“显示警告但仍允许点击开始”的行为必须移除。

### 4.4 关卡设计脚本

关卡搜索和阈值生成必须使用与产品层一致的有效区域计数规则。修复阶段不得依赖旧的 `KNOWN_E17B` 冻结集合继续生成非法关卡。

## 5. 9 个非法关卡修复策略

修复目标是让所有关卡初始局面通过 `validateBoard()`，而不是降低合法性规则。

| 关卡 | 当前问题 | 修复原则 |
|---|---|---|
| L-01 | 学院 ×2 | 改为合法的不同区域组合，保留读山母题 |
| L-02 | 学院 ×3 | 改为合法的不同区域组合，保留抱团母题 |
| L-03 | 学院 ×2 | 改为合法的不同区域组合，保留枢纽母题 |
| L-05 | 学院 ×4 | 改为合法的不同区域组合，保留组团母题 |
| L-06 | 学院 ×2、市政广场 ×2 | 市政广场保留至多一座，改用其他区域承担先修路母题 |
| L-07 | 学院 ×2、市政广场 ×2 | 市政广场保留至多一座，改用其他区域承担两头顾母题 |
| L-08 | 学院 ×3、市政广场 ×2 | 市政广场保留至多一座，重新校准韩国对照关 |
| L-09 | 书院 ×5 | 重新定义合法的韩国特色区域布局 |
| L-10 | 书院 ×2、圣地 ×2 | 重新定义合法的多目标布局 |

修复后必须重新生成并核对：

- `配置表/levels.csv`；
- `配置表/level_tiles.csv`；
- `tests/fixtures/levels_oracle.json`；
- `tests/levels.test.ts` 中的阈值与合法性断言；
- 贪心基线和三星阈值。

不允许通过删除 `E17b`、把错误改成警告、或绕过合法性校验来保留旧阈值。

## 6. 测试验收标准

新增或调整以下测试：

### 6.1 共享入口

- 地块级约束和城市级约束可以同时返回；
- 研究缺口使用结构化错误码；
- 每城上限和每玩家上限错误码不同；
- 文明替换后按有效区域计数；
- 错误顺序稳定。

### 6.2 UI

- 非法格置灰原因与统一校验结果一致；
- 科技 / 市政不足仍显示研究弹窗；
- 挑战预算耗尽时不能放置；
- 非法关卡的“开始”按钮被禁用或点击无效并展示原因。

### 6.3 关卡

- 所有关卡加载后 `validateBoard()` 无错误；
- 所有关卡初始状态未达成目标；
- 关卡约束值为正；
- 9 个关卡的最优产出与三星阈值重新一致；
- 不再保留 `KNOWN_E17B` 非空冻结集合。

### 6.4 回归

保持现有以下验收不变：

- 求值器 4 个不变量；
- 特色区域替换；
- 地貌移除；
- 多城区域唯一性；
- 区域相邻产出；
- Web 构建与配置校验。

## 7. 实施顺序

1. 新增 `src/legality.ts` 和结构化错误类型。
2. 将地块级约束迁入或包装进统一入口。
3. 迁移 `evaluate()`。
4. 迁移 `web/app.ts`。
5. 迁移 `web/levels.ts`，阻止非法关卡开始。
6. 补共享入口和错误顺序测试。
7. 重做 9 个非法关卡并更新 fixture、阈值、基线。
8. 运行完整验证。
9. 单独进入人口配额阶段。
10. 单独进入资源 / 奇观冲突阶段。

## 8. 非目标与风险

### 非目标

- 本阶段不确定人口配额公式；
- 不把资源或奇观冲突的推断写进正式规则；
- 不重写现有拆解案；
- 不迁移 Unity / C#；
- 不引入新的运行时依赖。

### 风险

1. 旧关卡阈值建立在非法重复区域上，修复后可能改变原母题。
2. `withDistrict()` 保持低层构造性质，调用方必须遵守“先校验、后写入”。
3. 如果错误码和旧中文文案同时维护，可能再次出现语义分叉；中文文案必须由结构化错误集中生成。
4. 关卡搜索器与产品校验器如果各自实现计数逻辑，仍可能生成新的非法关卡；二者应共享合法性模块或共享同一规则函数。

## 9. 当前批准范围

本规格对应用户已批准的第一阶段：

- 批准共享合法性入口；
- 批准挑战关卡加载拦截；
- 批准修复 9 个非法关卡；
- 暂不实现人口区域配额；
- 暂不实现资源 / 奇观冲突。
