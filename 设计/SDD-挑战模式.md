## 1. 设计目的

### 1.1 目标体验：在约束下找出最优布局

给定一个已经铺好的局面和一个明确目标，玩家要在有限的放置机会里达成它。

玩家在做的唯一一件事：**在信息完备的前提下做空间组合优化**——"最后三个区域放哪里，才能把生产力推过阈值？"

### 1.2 为什么是残局，而不是从零建城

残局是本项目范围控制的关键决策，它同时解决了三个问题：

| 问题 | 残局怎么解决 |
|---|---|
| 完整文明 6 要模拟回合、生产、科技推进，工作量不可控 | 残局只需**静态求值**，不需要任何时间维度 |
| 从零开局的前二十回合是重复劳动，与相邻加成无关 | 残局直接把玩家放在**决策最密集的时刻** |
| 难度不可控 | 残局的初始局面由设计者完全指定，难度可精确编排 |

**残局把一个 4X 游戏压缩成一道组合优化题，而这道题恰好是文明 6 区域规划的全部精华。**

### 1.3 关卡必须非平凡 ⭐

一个关卡如果能靠**贪心**通关——每步都放当前收益最高的区域——那它没有设计含量，它只是在考验玩家会不会看数字。

因此本模式给「关卡合格」下一个可计算的定义：

> **贪心基线必须失败。** 每个关卡在交付前都要跑一遍贪心基线脚本，贪心达不成目标而已验证的人工解能达成，这个关卡才算成立。

这条判据同时是设计约束和验收项。它逼出的关卡必然含有「局部最优 ≠ 全局最优」的结构——也就是真正的规划取舍。

## 2. 玩家侧流程

```
选关
   ↓
加载残局 ──► 加载时做合法性校验，非法局面直接报错（不带病进游戏）
   ↓
读目标（如：生产力 ≥ 目标值）与约束（如：可放置区域 3 个）
   ↓
┌─► 观察局面（与自由模式同样的完全信息）
│      ↓
│  悬停候选位 ──► 预览增量（与自由模式同一套求值）
│      ↓
│  放置 ──► 约束计数 −1，目标进度条刷新
│      ↓
│  ┌── 目标达成 ──────────────► 结算：评分 + 最终拆解
│  ├── 约束耗尽且未达成 ──────► 失败，可重试
│  └── 仍有余量 ──────────────┘ 回到观察
│
└─ 任意时刻可撤销（不消耗约束，见 §6 G4）
```

## 3. 规则定义

### 3.1 关卡的构成

一个关卡 = **初始局面** + **目标** + **约束** + **评分阈值**。

初始局面的内容与自由模式可编辑的内容完全一致（见 [SDD-自由模式.md](SDD-自由模式.md) §3.1），因此关卡可由自由模式直接导出。

### 3.2 目标

| 目标类型 | 判定 |
|---|---|
| 单一产出达标 | 指定产出类型的总值 ≥ 目标值 |
| 多产出同时达标 | 多个产出类型各自 ≥ 各自目标值 |
| 军事叠力达标 | 指定单位的**驻守战斗力** ≥ 目标值。定义见 [SDD-局面求值器.md](SDD-局面求值器.md) §3.9 |

判定读取的是求值器输出明细树的根层聚合值，**不另算一套**。

### 3.3 约束

约束限定玩家的操作预算。形态见 🔴 D2，当前倾向：**限定可放置区域数**。

理由：它与文明 6 本身的人口—区域数约束同构，玩家不需要学一套新概念；而且它直接作用在本作的核心决策对象（区域）上，不引入与相邻加成无关的资源管理。

### 3.4 达成判定的时机

**每次放置后立即判定。** 不需要玩家点"结束"——达成即结算。

理由：目标是产出阈值，而产出是局面的函数；玩家没有任何理由在达成后继续放置。设一个确认步骤只会增加一次无意义点击。

### 3.5 评分

**按最终产出值评级**（2026-09-25 改；原先按剩余约束，与目标值定法矛盾，详见 [关卡设计.md](关卡设计.md) §8）：

```
★★★  最终产出 ≥ 三星阈值   （＝设计期穷举出的最优值，找到最优解）
★★   最终产出 ≥ 二星阈值   （目标值与最优值的中点）
★     最终产出 ≥ 目标值     （通关）
失败   约束耗尽仍未达到目标值
```

三档阈值逐关配在 `levels.csv`，**都是产出值**，不是剩余约束。

三条实现要点：

- **判定用的产出值直接取求值器输出的根层聚合值**，与目标判定同一个数，不另算
- **允许二星阈值等于三星阈值**：产出粒度是 0.5，`V − 目标值 < 1` 的紧关卡放不下三档（见 [关卡设计.md](关卡设计.md) §8.2）
- **运行时不需要求解器**：三星阈值是设计期算好烧进表里的一个数字，运行时只比大小。这一点让评级与立项书暂缓清单里「不做求解器」不冲突

**多产出关卡的评级也是一个标量**：取目标向量各分量的**合计**。三星＝「在满足目标向量的布局里合计最高的那个」，不是全局合计最高——把预算全倒进一种产出的布局合计可能更高，但它没通关，不该参与评级。定法见 [关卡设计.md](关卡设计.md) §7.4。

> 这一段原先写的是「为什么不用『占最优解百分比』评分：那需要求解器」。**现在的方案实际上就是占最优解百分比**，只是求解发生在设计期而不是运行时——穷举一次，把最优值写进表。原来的理由把"需要最优值"和"需要运行时求解器"混为一谈了，其实前者不蕴含后者。

## 4. 数据结构

关卡**全部配表驱动**，不用 JSON——这样跨表校验脚本能一并校验关卡，且与项目其余部分的约定一致。

### `levels.csv`（关卡元数据，一关一行）

| 字段 | 说明 |
|---|---|
| 关卡id | 稳定唯一，如 `L-03` |
| 名称 | 玩家可见 |
| 文明id / 领袖id | 引用 `civs` / `leaders` |
| 已解锁科技 / 已解锁市政 | `\|` 分隔的 id 列表（求值器必需，见其 §3.2） |
| 城市中心坐标 / 人口 | 决定工作范围与区域数上限 |
| 目标类型 | `单一产出达标` / `多产出同时达标` / `军事叠力达标`，见 §3.2 |
| 目标产出类型 | 单产出写一种；多产出写 `\|` 分隔的产出类型列表，如 `科技\|信仰` |
| 目标值 | 单产出是一个数；**多产出是 `\|` 分隔的 `产出类型:值` 向量**，如 `科技:4\|信仰:3` |
| 约束类型 / 约束值 | 见 §3.3 |
| 三星阈值 / 二星阈值 | **产出值**，见 §3.5。必须满足 `目标值 ≤ 二星 ≤ 三星`。多产出关卡的阈值是**各产出的合计**（见 [关卡设计.md](关卡设计.md) §7.4） |
| 关卡类别 | `普通` / `教学` / `对照`。三类的判据各不相同，见 [关卡设计.md](关卡设计.md) §1：普通关要求贪心失败，教学关允许贪心通过（§1.1），对照关的判据是交叉代入劣化（§1.2） |
| 母题 | 该关卡针对的关卡母题标识（A–F），**可以是 `+` 连接的组合**（L-07 = `B+C`），见 [关卡设计.md](关卡设计.md) §2 |
| 贪心基线结果 | 交付前跑出的贪心达成值，用于证明关卡非平凡。**形态必须与 `目标值` 一致**（多产出也写成向量），因为判定要逐项比较而不是比合计，理由见 [关卡设计.md](关卡设计.md) §7.4。**贪心的精确定义见同文档 §7**，不在本文件重复 |

### `level_tiles.csv`（关卡初始局面，一格一行）

| 字段 | 说明 |
|---|---|
| 关卡id | 外键 |
| 坐标 | 轴向坐标 |
| 地形 / 地貌 / 资源 / 自然奇观 | 引用各自的表 |
| 河流边 | 哪几条边是河 |
| 初始区域 | 空则为空地 |
| 初始建筑 | `\|` 分隔 |

⭐ 把「贪心基线结果」作为一个**字段存进表里**，而不是只写在文档里：这样任何人（包括面试官）都能看到每个关卡的非平凡性是被验证过的，而不是设计者自称的。

## 5. 状态机

```
   ┌──────────┐ 加载成功  ┌──────────┐
   │ Loading  │─────────►│ Playing  │◄──┐
   │ 校验局面  │          │          │   │ 放置 / 撤销
   └────┬─────┘          └────┬─────┘───┘
        │ 校验失败              │
        ▼                      ├── 达成目标 ──► ┌──────────┐
   ┌──────────┐                │                │ Settled  │
   │  Error   │                │                │ 评分结算  │
   │ 报错不进入 │                │                └────┬─────┘
   └──────────┘                │                     │ 重试
                               └── 约束耗尽 ──► ┌──────────┐
                                               │ Failed   │
                                               └────┬─────┘
                                                    │ 重试
                                                    └──► Loading
```

`Loading` 阶段的校验不可跳过：一个非法的初始局面会让后续所有求值结果失去意义，且极难排查。

## 6. 边界情况

| # | 情况 | 处理 |
|---|---|---|
| G1 | 初始局面已经达成目标 | **加载时校验拦截**，这是关卡配错。目标值必须严格高于初始局面的产出 |
| G2 | 初始局面非法（区域超范围 / 超上限 / 前置不满足） | 报错，不进入游戏 |
| G3 | 约束值为 0 | 同 G1，配错 |
| G4 | 撤销是否返还约束 | **返还**。约束是"最终布局用了几个区域"的预算，不是"操作次数"。不返还会让玩家因试错而被惩罚，与完全信息的设计前提矛盾 |
| G5 | 玩家用完约束但不点任何按钮 | 立即判失败并给重试入口，不等待 |
| G6 | 无合法空格可放但仍有剩余约束 | 立即判定：若已达成则结算，否则失败 |
| G7 | 多目标中部分达成 | 全部达成才算达成；进度条分项显示 |
| G8 | 达成的同一回合内约束正好耗尽 | **达成优先**，判定为成功 |
| G9 | 关卡引用了不存在的文明 / 科技 / 地形 id | 跨表校验拦截，不进入运行时 |
| G10 | 贪心基线字段为空的关卡 | **不得交付**。视为未完成验证 |
| G11 | 贪心基线结果 ≥ 目标值，且 `关卡类别=普通` | **关卡不合格**，校验脚本拦截。见 [关卡设计.md](关卡设计.md) §5.2 |
| G12 | `关卡类别=对照` 但找不到同地形的伙伴关卡 | **关卡不合格**，校验脚本规则 18 拦截。对照关要证明「换文明会换解法」，地形必须逐格相同，见 [关卡设计.md](关卡设计.md) §1.2 |
| G13 | 多产出关卡的贪心基线合计已超过目标合计，但有分量未达标 | **关卡仍然合格**。判定逐项比较，不比合计，见 [关卡设计.md](关卡设计.md) §7.4 |

G4 与 G8 是两处「偏向玩家」的裁定。它们的共同理由：本作的挑战是**算清楚**，不是操作精度，任何把失败归因于试错或时序的规则都偏离了设计目的。

## 7. 与其他系统的接口

| 方向 | 对象 | 数据 |
|---|---|---|
| 输入 | `levels.csv` / `level_tiles.csv` | 关卡定义 |
| 输出 | 求值器 | 局面（含科技市政集合） |
| 输入 | 求值器 | 产出明细树 → 目标判定与进度条 |
| 输入 | 自由模式 | 导出的关卡草稿 |

本模式**不含产出规则**，目标判定只读求值器输出的聚合值。

## 8. 验收标准

### 关卡加载

- [ ] 合法关卡正常加载；G1–G3、G9 各类配错在加载时被拦截并给出可读原因
- [ ] 加载后的局面求值结果与自由模式中手工搭出同一局面的结果完全一致

### 玩法

- [ ] 悬停预览与实际放置增量一致（与自由模式同一套求值）
- [ ] 每次放置后立即判定，达成即结算
- [ ] 目标进度条对多目标分项显示
- [ ] 撤销返还约束（G4）
- [ ] G5–G8 的判定行为符合本文档

### 关卡质量（每关逐条过）

- [ ] 有至少一个已验证的人工达成解
- [ ] **贪心基线无法达成目标**（`关卡类别=普通` 的关卡；教学关与对照关豁免），且基线结果已写入 `levels.csv`
- [ ] 对照关有同地形、不同文明的伙伴关卡，且**交叉代入双向劣化**（见 [关卡设计.md](关卡设计.md) §1.2）
- [ ] 贪心基线可复现：同一关卡重复跑出完全相同的结果（依赖 [关卡设计.md](关卡设计.md) §7.2 的平局规则）
- [ ] 三星阈值等于设计期穷举出的最优值，且该值确实可达（穷举保证）
- [ ] 星级判定读的是求值器的聚合产出，与目标判定同一个数

## 10. 🔴 待决策清单

**✅ D1 · 「军事叠力」目标 —— 已解除（2026-09-23）**
定义为单个单位叠满加成后的最终战斗力，实现取驻守战斗力。军事类关卡形态随之明确：给定一个单位与一片地形，玩家通过调整站位、驻守、大将军位置、友军相邻布置来把该单位的战斗力推过阈值。

⚠️ 但军事关卡的**数值**仍被阻塞：受损惩罚曲线（求值器 D9）与多大将军叠加（求值器 D8）都待一手核对。**首批关卡仍只做产出类目标**，军事关卡等数据到位。

⭐ 军事关卡与产出关卡在设计上是同构的：都是"在稀缺的格子上安排对象，让相邻与条件修正叠到最大"。这意味着挑战模式不需要为军事目标做任何额外的玩法机制——**只是换一棵树来读**。

**🔴 D2 · 约束形态**

| 方案 | 说明 |
|---|---|
| 限定可放置区域数（推荐） | 与文明 6 的人口—区域约束同构，不引入新概念 |
| 给定建造预算（生产力/金币） | 更贴近真实游戏，但需要把建造成本纳入模型，且与"静态求值"的定位有张力 |
| 限定区域类型配额 | 例如"只能放 1 个学院"，能制造很别致的题目，但更像谜题而非规划 |

**D3 · 关卡数量与难度梯度**（待数值到位后在 `数值设计.md` 中定）

**D4 · 是否需要提示系统**（完全信息下提示等于给答案，倾向不做）
