## 0. 三类检查的分工

## 2. 数值对账 ★ 本文件的核心

### 2.0 通用方法

**目标**：构造一个**只有一个变量**的观测局面，使某条规则的贡献可以被单独读出。

三个可用的读数工具，按可靠性排序：

| 工具 | 读什么 | 适用 |
|---|---|---|
| **区域放置预览** | 悬停候选格时显示该格建成后的产出 | 相邻加成，**不需要真的建造**，成本最低 |
| 城市详情面板的产出明细 | 城市各产出的分项来源 | 判断小数是否在城市级累积 |
| **战斗预览面板** | 发起攻击时逐条列出修正项及数值 | 军事叠力，这是游戏自己给出的逐条拆解 |

**两条纪律**：

1. **每次只改一个变量。** 要测「相邻雨林」就必须确认该格周围没有山脉、地热裂缝、礁石等其他科技来源。
2. **同时记区域读数与城市总产出读数。** 只看区域面板会漏掉"小数在城市级累积"这种实现（见 §2.1 模型 C）。这是最容易漏的一步。

> 如果《风云变幻》的 World Builder 支持直接摆放地貌与区域，用它构造局面会快得多。我不确定它的粒度支持到哪一步，你比我熟——若支持，下面所有实验都可以在一个自建地图里几分钟做完；若不支持，就在正常对局里找地形。

### 2.1 🔴 D4 · 标准档的取整规则（**最高优先级**）

**为什么最高**：它影响每一条标准档规则的每一次求值。定错一次，全部拆解结论作废。

**低成本做法**：不要用「相邻区域」来测（要真造出好几个区域，很贵）。用 **`Jungle_Science`**——学院相邻雨林，同样是标准档（`所需数量=2`，`加成值=1`），而雨林是地貌，**找到就能测，零建造成本**。

#### 实验一：单一标准档规则的取整

找一片平坦草原（**确认六格邻域内无山脉、地热裂缝、礁石**），使学院候选格的相邻雨林数可控。用放置预览逐一读数：

| 相邻雨林数 | 预览显示的科技 | 城市总科技增量 |
|---|---|---|
| 0 | | |
| 1 | | |
| 2 | | |
| 3 | | |
| 4 | | |
| 5 | | |

三种候选模型给出不同的序列：

| 模型 | 含义 | N=0..5 的预期序列 |
|---|---|---|
| **A 逐规则整除截断** | 每条规则独立算 `floor(n/2)×1` | 0, 0, 1, 1, 2, 2 |
| **B 逐规则保留小数，汇总后取整** | 每个雨林贡献 0.5 | 0, 0（或 0.5）, 1, 1（或 1.5）, 2, 2（或 2.5） |
| **C 区域面板取整，城市级累积小数** | 区域显示取整值，但城市总产出吃到小数 | 区域列同 A，**城市列不同** |

#### 实验二：两条标准档规则的小数会不会汇合（**D4 的真正难点**）

这一条比实验一更关键，也更容易被忽略。

构造：学院候选格**恰好相邻 1 个雨林 + 恰好 1 个其他区域**，其余邻格无任何科技来源。

| 模型 | 预期 |
|---|---|
| A 逐规则截断 | 两条规则各 `floor(1/2)=0` → **+0** |
| B 小数汇合 | 0.5 + 0.5 → **+1** |
| C | 区域面板 0，城市总产出 +1 |

**结果直接决定求值器 §3.3 的 `g` 函数与 §3.5 第 8 步的取整时机。** 三个模型的实现完全不同，不能"先按一个写，以后再改"——它会污染全部关卡目标值。

#### 实验三：主要档基线（顺带确认，成本极低）

学院相邻 N 座山脉（`所需数量=1`，`加成值=1`），预期严格线性 `+N`。

| 相邻山脉数 | 预览显示的科技 |
|---|---|
| 1 | |
| 2 | |
| 3 | |

⚠️ 注意山脉有 5 个地形变体（草原/平原/沙漠/苔原/雪地山脉），**混用不同变体也应当是 +N**——如果不是，说明我们对「5 条规则各自独立计数」的理解有误。顺手验证一下。

### 2.2 🔴 D10 · `Self` 类别的求值语义

唯一一条 `Self="true"` 规则是韩国书院的 `BaseDistrict_Science`（+4 科技）。区域不可能与自己相邻，所以这条在效果上像"固定值"。

**实验**：用韩国开局，在一个**六格邻域内没有任何区域、没有山脉、没有雨林**的位置放书院，读预览科技。

| 观测 | 结论 |
|---|---|
| 显示 +4 | `Self` 是无条件固定值 → 求值器当**常数项** |
| 显示 +0 或别的值 | 有隐含条件，需继续查 |

**同时验证书院的净收益曲线**（这条决定第三模式能不能借用它的手法）：

| 相邻区域数 | 预期（若 +4 固定、每相邻 −1） | 实测 |
|---|---|---|
| 0 | +4 | |
| 1 | +3 | |
| 2 | +2 | |
| 4 | +0 | |
| 5 | −1？还是截断在 0？ | |

最后一行是个真问题：**负产出会不会被截断在 0**。求值器边界 E21 对战斗力定了下限 1，产出侧还没定。

### 2.4 科技门控（对象已更正）

⚠️ **这一节的对象在 2026-09-24 改了。** 原本要验「相邻加成随科技变化」，但解析后确认**区域侧 103 条相邻规则中 0 条带前置条件**（那 19 条 `前置科技` 全在改良设施侧，本期不做）。所以要验的不再是产出，而是**可建性**：

| 待验 | 数据依据 | 做法 |
|---|---|---|
| 区域可建性随科技变化 | `districts` 36 行中 23 行带前置科技、11 行带前置市政 | 选一个带前置科技的区域，在解锁前后各看一次建造列表 |
| 建筑可建性随科技变化 | `buildings` 85 行中 41 行带前置科技、20 行带前置市政 | 同上 |
| **相邻加成不随科技变化** | 区域侧 0 条带条件 | 同一布局在不同科技阶段读两次产出，**应当完全相同**。这是个反向验证，用来确认我们没漏掉隐藏的门控 |

最后一行值得做：它验证的是一条"什么都不该发生"的结论，而这类结论最容易被漏掉的规则推翻。

### 2.4b 数据里没有表达、只能实测的两项

这两项的共同特点是**游戏数据里查不到答案**——不是没找到，是数据结构里不存在这个信息。所以不能写成假设放进实现，必须实测。

| # | 待测 | 为什么数据里没有 | 做法 |
|---|---|---|---|
| 1 | **区域配额上限的取整方式** | XML 只有分母 `DISTRICT_POPULATION_REQUIRED_PER = 3`，取整发生在引擎里。`ceil(人口/3)` 还是 `floor(人口/3)+1`，两者在人口 3、6、9 处结果不同 | 用一座城把人口从 1 养到 7，每次记录可建专业化区域数上限 |
| 2 | **世界奇观所在的格算不算「任意其他区域」** | 世界奇观是 `Buildings` 而不是 `Districts`，`OtherDistrictAdjacent` 是否把它算进去，数据无从表达 | 找一个剧院广场候选格，邻格恰好只有 1 个世界奇观、无其他区域，读预览文化。算 → 吃到 `District_Culture`；不算 → 只吃 `Wonder_Culture` |

第 2 项的影响不小：若世界奇观计入，剧院广场的相邻上界从 +11 升到 +14，关卡目标值的量级要跟着调。

## 3. 通关路径 checklist

实现完成后按顺序走一遍。**任一步失败即中止**，不要跳过继续往下走。

### 自由模式

- [ ] 启动后能选文明与领袖，切换后特色区域替换立即生效（用韩国验证：学院变书院）
- [ ] 科技阶段可见且可调
- [ ] 地图上能编辑地块的地形 / 地貌 / 资源
- [ ] 悬停空格显示放置预览，**预览的产出差额与实际放置后的差额完全一致**
- [ ] 悬停非法格显示不可放置的原因
- [ ] 放置后产出拆解面板刷新，能逐层下钻到规则 id
- [ ] 增量为 0 的规则灰显保留；前置未满足的规则标注所缺前置
- [ ] 面板任一层级求和等于上层，**不出现「其他」项**
- [ ] 多步撤销后产出与撤销前的对应局面完全一致
- [ ] 导出关卡草稿，能被挑战模式直接加载

### 挑战模式

- [ ] 关卡列表可见，教学关与主序列分组清晰
- [ ] 加载合法关卡正常；配错的关卡在加载时被拦截并给出可读原因
- [ ] 加载后的局面求值结果与自由模式手工搭出同一局面的结果完全一致
- [ ] 悬停预览与实际放置增量一致（与自由模式同一套求值）
- [ ] 每次放置后立即判定；达成即结算
- [ ] 目标进度条对多目标分项显示
- [ ] 撤销返还约束
- [ ] 约束耗尽且未达成 → 判失败并给重试入口
- [ ] 结算页显示评级与最终拆解
- [ ] L-08 与 L-09 同地形不同文明，**最优布局方向相反**（成团 vs 孤立）

### 跨系统

- [ ] 同一局面在自由模式与挑战模式下产出完全相同
- [ ] 打乱放置顺序构造同一最终局面，产出恒等（求值器不变量 I3）
- [ ] 改一行 `adjacency_rules.csv` 的数值后重启，拆解面板与关卡最优解随之改变

## 4. 回归影响矩阵

改了左边，必须重跑右边。**这张表的作用是防止"改了配置表忘了重算贪心基线"这类静默失效。**

| 改动 | 必须重跑 |
|---|---|
| `parse_civ6_xml.py` | 全表重生成 + md5 比对 + `check_config` + §2 抽样对账 |
| `adjacency_rules.csv` | `check_config` + 求值器单测 + **全部关卡的贪心基线** + 关卡非平凡性复核 |
| 其他生成表 | `check_config` + 求值器单测 |
| `字段说明.md` 的字段或枚举 | 同步 `check_config.py` 的 `SCHEMA`/`ENUMS` + `test_check_config.py` 补断言 + 全表重校验 |
| 求值器 | 全部单测 + 四条不变量测试 + §2 的全部对账用例 |
| `levels.csv` / `level_tiles.csv` | 该关的贪心基线 + 人工解复核 + 关卡非平凡性 |
| 校验规则 | `test_check_config.py` 补一条断言（这条是硬要求，见 `Tools/testdata/README.md`） |
