## 0. 三类检查的分工

| 类别 | 由谁执行 | 何时跑 |
|---|---|---|
| 自动化检查 | 脚本 | 每次改配置表或代码 |
| **数值对账** | **人 + 开着游戏** | 数值来源变化时；未决项定案前 |

## 2. 数值对账 ★ 本文件的核心

### 2.0 通用方法

**目标**：构造一个**只有一个变量**的观测局面，使某条规则的贡献可以被单独读出。

三个可用的读数工具，按可靠性排序：

| 工具 | 读什么 | 适用 |
|---|---|---|
| **区域放置预览** | 悬停候选格时显示该格建成后的产出 | 相邻加成，**不需要真的建造**，成本最低 |
| 城市详情面板的产出明细 | 城市各产出的分项来源 | 判断小数是否在城市级累积 |
| **战斗预览面板** | 发起攻击时逐条列出修正项及数值 | 军事叠力，这是游戏自己给出的逐条拆解 |

**两条纪律**：

1. **每次只改一个变量。** 要测「相邻雨林」就必须确认该格周围没有山脉、地热裂缝、礁石等其他科技来源。
2. **同时记区域读数与城市总产出读数。** 只看区域面板会漏掉"小数在城市级累积"这种实现（见 §2.1 模型 C）。这是最容易漏的一步。

> 如果《风云变幻》的 World Builder 支持直接摆放地貌与区域，用它构造局面会快得多。我不确定它的粒度支持到哪一步，你比我熟——若支持，下面所有实验都可以在一个自建地图里几分钟做完；若不支持，就在正常对局里找地形。

### 2.1 ✅ D4 · 标准档的取整规则（**已于 2026-09-24 完成，结论见 §2.6**）

> 以下实验方案保留作为方法记录。结论已写进 [SDD-局面求值器.md](SDD-局面求值器.md) §3.3。
> **剩下一个次要未验项**：城市级每回合产出是否取整（原第五步未做，见 SDD §10 D11）。

**为什么最高**：它影响每一条标准档规则的每一次求值。定错一次，全部拆解结论作废。

**低成本做法**（2026-09-24 改进）：用**圣地 + 森林**，而不是学院 + 雨林，也不要用「相邻区域」。

| | 圣地 + `Forest_Faith` | 学院 + `Jungle_Science` |
|---|---|---|
| 标准档规则 | 森林 每 2 个 +1 信仰 | 雨林 每 2 个 +1 科技 |
| 要排除的其他同产出来源 | 7 项（山脉 ×5、政府广场、自然奇观、棉花堡） | **10 项**（山脉 ×5、政府广场、大堡礁、地热裂缝、棉花堡、礁石） |
| 目标地貌的常见度 | 森林，绝大多数开局都有 | 雨林，要热带开局 |
| 前置 | 占星术 | 书写 |

**另一个省事的地方：城市中心本身就是一个区域。** `OtherDistrictAdjacent`（任意其他区域）理论上把城市中心算进去，所以测「相邻区域」这一档**不需要真的造任何区域**——把圣地候选格放在城市中心旁边就有 1 个区域邻居了。这一点本身也要顺带验证（步骤 3）。

#### 四步序列（前三步全靠放置预览，零建造）

每一步都要求候选格的六格邻域里**除了指定的东西以外，没有任何其他信仰来源**（山脉、政府广场、自然奇观、棉花堡、其他区域）。

| 步骤 | 候选格邻域 | 目的 | 读数 |
|---|---|---|---|
| **1 校准** | 恰好 2 片森林 | 确认规则生效、干扰排除成功。**所有模型都预期 +1** | |
| **2 关键** | 恰好 1 片森林 | 区分「整除截断」与「保留小数」 | |
| **3 前提** | 恰好城市中心、无森林 | 城市中心算不算「任意其他区域」 | |
| **4 决定性** | 恰好 1 片森林 + 城市中心 | 两条标准档规则的小数会不会汇合 | |

**步骤 1 如果不是 +1，先别往下走**——说明邻域没排干净，或者我们对这条规则的理解有错。

#### 读数怎么解释

| 步骤 2 读数 | 步骤 4 读数 | 结论 |
|---|---|---|
| 0 | 0 | **模型 A 逐规则整除截断**。`g = floor(n/所需数量) × 加成值` |
| 0 | +1 | **模型 B 小数汇合后取整**。每个目标贡献 `加成值/所需数量`，汇总后取整 |
| 显示 0.5 | +1 | 模型 B，且界面直接显示小数 |
| +1 | +1 或 +2 | 所需数量 2 不是"每 2 个"，我们对档位语义的理解需要重查 |

（若步骤 3 读数为 0，则步骤 4 的「城市中心」这一份可能根本没参与，需换成真造一个区域来做步骤 4。）

三种候选模型给出不同的序列：

| 模型 | 含义 | N=0..5 的预期序列 |
|---|---|---|
| **A 逐规则整除截断** | 每条规则独立算 `floor(n/2)×1` | 0, 0, 1, 1, 2, 2 |
| **B 逐规则保留小数，汇总后取整** | 每个雨林贡献 0.5 | 0, 0（或 0.5）, 1, 1（或 1.5）, 2, 2（或 2.5） |
| **C 区域面板取整，城市级累积小数** | 区域显示取整值，但城市总产出吃到小数 | 区域列同 A，**城市列不同** |

#### 第五步：小数是不是在城市级累积（需要真造一座）

前四步只用放置预览，读的是**区域面板的数字**。但还有一个模型读不出来：

> **模型 C**：区域面板显示取整值，而城市总产出吃到小数。

要排除它，必须在步骤 4 的局面下**真的建一座圣地**，然后比对：

- 建造前城市总信仰 = ___
- 建造后城市总信仰 = ___
- 区域面板显示的相邻加成 = ___

若「城市总增量」大于「区域面板显示值 + 该区域的建筑与市民产出」，就是模型 C。

**只需要建这一座。** 前四步的结论足以定 `g` 的形态，这一步只定取整发生在哪一层。

> 结果直接决定求值器 §3.3 的 `g` 函数与 §3.5 第 9 步的取整时机。三个模型的实现完全不同，**不能"先按一个写，以后再改"**——它会污染全部关卡目标值。

#### 顺带做：主要档基线（成本极低）

圣地相邻 N 座山脉（`所需数量=1`，`加成值=1`），预期严格线性 `+N`。

| 相邻山脉数 | 预览显示的信仰 |
|---|---|
| 1 | |
| 2 | |
| 3 | |

⚠️ 注意山脉有 5 个地形变体（草原/平原/沙漠/苔原/雪地山脉），**混用不同变体也应当是 +N**——如果不是，说明我们对「5 条规则各自独立计数」的理解有误。顺手验证一下。

### 2.2 🔴 D10 · `Self` 类别的求值语义

唯一一条 `Self="true"` 规则是韩国书院的 `BaseDistrict_Science`（+4 科技）。两种读法：**A** 无条件固定 +4；**B** 字面的"与同类相邻"，即挨着**另一座书院**才 +4。

> 本节此前写"区域不可能与自己相邻，所以这条像固定值"——**该论证已撤回**（SDD §10 D10）：读法 B 说的是相邻另一座同类型区域，两座书院并排完全可能。现有的先验证据是提示文本（103 条相邻规则里 102 条点明来源，只有这条不点明），但文案不等于算法，所以这条实测仍然必须做。

**实验一 · 判别读法**：用韩国开局，在一个**六格邻域内没有任何区域、没有山脉、没有雨林**的位置放书院，读预览科技。

| 观测 | 结论 |
|---|---|
| 显示 +4 | 读法 A：无条件固定值 → 求值器当**常数项**（维持现状） |
| 显示 +0 | 读法 B：与同类相邻 → 把 `SELF_IS_FIXED_VALUE` 翻成 `false` |
| 别的值 | 有第三种隐含条件，需继续查 |

> ⚠️ **不要用"两座书院并排"做这个实验。** 两种读法在那个局面下都算出合计 6，是唯一不可区分的局面（SDD §10 D10 的实算表）。有判别力的是**孤立书院**（4 还是 0）与**三座书院连成一串**（合计 8 还是 12）。若条件允许，顺手把三连排也测一下当交叉验证。

**同时验证书院的净收益曲线**（这条决定第三模式能不能借用它的手法）：

| 相邻区域数 | 预期（若 +4 固定、每相邻 −1） | 实测 |
|---|---|---|
| 0 | +4 | |
| 1 | +3 | |
| 2 | +2 | |
| 4 | +0 | |
| 5 | −1？还是截断在 0？ | |

最后一行是个真问题：**负产出会不会被截断在 0**。求值器边界 E21 对战斗力定了下限 1，产出侧还没定。

### 2.4b 数据里没有表达、只能实测的两项

这两项的共同特点是**游戏数据里查不到答案**——不是没找到，是数据结构里不存在这个信息。所以不能写成假设放进实现，必须实测。

| # | 待测 | 为什么数据里没有 | 做法 |
|---|---|---|---|
| 1 | **区域配额上限的取整方式** | XML 只有分母 `DISTRICT_POPULATION_REQUIRED_PER = 3`，取整发生在引擎里。`ceil(人口/3)` 还是 `floor(人口/3)+1`，两者在人口 3、6、9 处结果不同 | 用一座城把人口从 1 养到 7，每次记录可建专业化区域数上限 |

## 3. 通关路径 checklist

实现完成后按顺序走一遍。**任一步失败即中止**，不要跳过继续往下走。

### 自由模式

- [ ] 启动后能选文明与领袖，切换后特色区域替换立即生效（用韩国验证：学院变书院）
- [ ] 科技阶段可见且可调
- [ ] 地图上能编辑地块的地形 / 地貌 / 资源
- [ ] 悬停空格显示放置预览，**预览的产出差额与实际放置后的差额完全一致**
- [ ] 悬停非法格显示不可放置的原因
- [ ] 放置后产出拆解面板刷新，能逐层下钻到规则 id
- [ ] 增量为 0 的规则灰显保留；前置未满足的规则标注所缺前置
- [ ] 面板任一层级求和等于上层，**不出现「其他」项**
- [ ] 多步撤销后产出与撤销前的对应局面完全一致
- [ ] 导出关卡草稿，能被挑战模式直接加载
