## 2. 系统关系图

```
┌─────────────────────────────────────────────────────────────┐
│ 配置表层（唯一事实来源，由游戏数据解析生成）                    │
│  terrains / features / resources / wonders                   │
│  districts / buildings / units                               │
│  civs / leaders / unique_districts                           │
│  adjacency_rules ★                                           │
└────────────────────────┬────────────────────────────────────┘
                         │ 全量规则与数值
                         ▼
┌─────────────────────────────────────────────────────────────┐
│ 局面求值器  evaluate(boardState) -> 产出明细树                 │
│                                                              │
│  地块层 ──基础产出 + 相邻资格标签──┐                           │
│  区域层 ──区域基础产出─────────────┤                           │
│  相邻层 ──逐条规则求值 + 规则id────┼──► 产出明细树              │
│  建筑层 ──建筑增量 + 前置校验──────┤                           │
│  文明层 ──规则替换 + 产出修正──────┘                           │
└──────────┬──────────────────────────────┬───────────────────┘
           │ 产出明细树                     │ 产出明细树
           ▼                               ▼
   ┌───────────────┐              ┌────────────────────┐
   │   自由模式     │              │     挑战模式        │
   │ 拆解面板渲染   │              │ 目标判定 + 约束计数  │
   │ 悬停预览       │              │ 评分与结算          │
   └───────────────┘              └────────────────────┘
```

### 每条边传什么

| 边 | 传递的数据 |
|---|---|
| 配置表 → 求值器 | 全量规则行。求值器**不硬编码任何规则**，换一套表即换一套玩法 |
| 地块层 → 相邻层 | 每个地块的**相邻资格标签**（是山脉？是河流？有什么资源？上面是什么区域？） |
| 区域层 → 相邻层 | 被求值区域的 id 与位置，用于检索适用的相邻规则 |
| 文明层 → 区域层 | **替换关系**（汉萨替换工业区）与产出修正。替换发生在求值之前 |
| 求值器 → 两模式 | **产出明细树**：不是一个数字，是一棵可展开到规则行的树 |
| 两模式 → 求值器 | 局面（boardState）。**单向**，模式层不回写求值器状态 |

⭐ 求值器**只出不进**——它不知道自己被谁调用，也不知道调用结果被用来渲染面板还是判定胜负。这使同一个函数能同时服务实时预览、目标判定和将来的批量求解。

## 3. 两个模式的核心循环

### 自由模式

```
选文明 + 领袖
     ↓
观察地块（地形/地貌/资源可见）
     ↓
悬停候选位 ──► 预览：放下去产出变成多少，差额多少
     ↓
放置区域 / 建筑
     ↓
拆解面板刷新 ──► 看到这一点产出由哪几条规则贡献
     ↓
调整（撤销 / 换位置 / 换区域）
     └──────────► 回到观察
```

**无胜负条件。** 驱动力是理解而非达成：玩家在做的事是"搞清楚这套规则怎么运作"。这决定了拆解面板是本模式的全部体验，不是辅助信息。

### 挑战模式

```
加载残局（已有地块 + 已有区域建筑 + 文明领袖固定）
     ↓
读目标（生产力 / 科技 / 军事叠力 达到 N）与约束
     ↓
规划 ──► 悬停预览（与自由模式同一套）
     ↓
放置 ──► 目标进度条变化 + 约束计数减少
     ↓
┌── 达成目标 ──► 结算与评分
└── 约束耗尽 ──► 失败，可重试
```

## 4. 信息设计

| 信息 | 可见性 | 理由 |
|---|---|---|
| 地块的地形 / 地貌 / 资源 | ✅ 全部可见 | |
| 每条相邻规则的存在与数值 | ✅ 全部可见 | |
| 放置前的产出预览 | ✅ 实时 | |
| 产出的规则级拆解 | ✅ 可展开 | 本作的核心体验 |
| 挑战模式的目标与约束 | ✅ 开局即给 | |

**本作是完全信息博弈。** 两个理由：

1. **还原保真**：文明 6 本身就把相邻加成预览完整展示给玩家，隐藏它就不是还原
2. **乐趣来源是组合优化，不是信息博弈**。这里的试错是噪音，不是玩法

> 与 `武侠RPGdemo` 的对照：那边「敌人弱点初始隐藏、命中后永久显形」，因为**试错本身是核心玩法**；这边全部公开，因为**算清楚才是核心玩法**。两个 demo 对同一个问题给出相反答案，且各有理由——这个对照本身是作品集素材。

### 产出拆解面板（体验命脉）

每一点产出都能展开到**贡献它的规则行**。没有"其他"项，没有合并项。

```
科技 +7.5
├─ 学院 @ (2,-1)                              +5.5
│   ├─ 相邻 山脉 ×2（主要档 +1/个）             +2.0   [DISTRICT_CAMPUS@Mountains_Science1]
│   │                                                 [DISTRICT_CAMPUS@Mountains_Science2]
│   ├─ 相邻 其他区域 ×3（标准档 +1/2个）         +1.5   [DISTRICT_CAMPUS@District_Science]
│   └─ 图书馆                                  +2.0   [BUILDING_LIBRARY]
└─ 城市中心 @ (0,0)                            +2.0
    └─ 宫殿                                    +2.0   [BUILDING_PALACE]
```

这个示例里有三处值得注意，都是实测与解析后才敢写实的：

- **没有「区域基础产出」这一行。** 文明 6 的区域自身零产出，学院的 5.5 全部来自相邻加成与建筑（见 [../拆解/文明6-产出与相邻加成体系.md](../拆解/文明6-产出与相邻加成体系.md) §2.2）。面板不该给一个恒为 0 的行留位置。
- **标准档是 +1.5 而不是 +1。** 3 个相邻区域 × 1 ÷ 2 = 1.5，不截断（[SDD-局面求值器.md](SDD-局面求值器.md) §3.3）。**小数必须显示**，这是游戏本身的行为。
- **山脉那一档是两条独立规则。** 文明 6 没有统一的"山脉"地形，五个地形变体各一条规则。面板上应当合并展示为「相邻 山脉 ×2」但保留两个规则 id 可追溯——**展示按玩家的概念分组，追溯按数据的实际结构**。

⭐ **方括号里的规则 id 是这个面板的灵魂**。它把"这个数字是多少"变成"这个数字凭什么是这样"，也使任何一处数值错误都能被追到具体的表行。演示时这一列是最有说服力的东西。

## 6. 验证指标

「哪些数据说明设计成功」——作品集的差异化项，也是自查清单。

| 指标 | 达标判据 | 不达标说明什么 |
|---|---|---|
| **数值保真** | 与游戏内已知局面的对账通过率 100% | 解析或规则理解有误 |
| **拆解完备** | 任一产出总值 = 其所有叶子节点之和，无"其他"项 | 有规则没被建模，被糊进了常数 |
| **关卡非平凡** | 纯贪心放置（每步选当前收益最高）**无法**达成目标 | 关卡没有规划含量，退化成点最大值 |
| **关卡可解** | 每个关卡至少有一个已验证的达成解 | 关卡不可解 |
| **文明有差异** | **交叉代入双向劣化**：把 A 文明的最优布局照搬给 B 文明，B 的得分严格低于 B 自己的最优，反向亦然 | 特色区域只是换皮，没进规则 |
| **配置表在驱动** | 改一行 `adjacency_rules`，最优布局随之改变 | 表只是装饰，规则实际硬编码在代码里 |

「关卡非平凡」是这套指标里最重要的一条：它给"这个关卡有没有设计含量"下了一个**可计算的定义**，而不是靠手感判断。

### 6.1 两条指标的判据是后来才变得可计算的

上面两条加粗的判据不是一开始就这么写的，它们各自被一次实测逼着改过：

- **「文明有差异」原先写的是「最优布局结构性改变」。** "结构性"不可计算——两个布局长得不一样到什么程度才算结构性不同？改成**交叉代入双向劣化**后它变成一个数：把 A 的最优布局照搬给 B，B 亏多少。而且这个判据更贴题：它**排除了"只是数值缩放"这个平凡解释**（若某文明只是整体强 20%，交叉代入不会劣化）。实测 L-08 ↔ L-09 为 60% / 58%，见 [关卡设计.md](关卡设计.md) §1.2。
- **「关卡非平凡」的贪心基线被加强过一次。** 原先按固定顺序打破平局，结果一个毫无设计含量的盘面也能"通过"（母题 A 的假阳性）。现在贪心在平局处取最优分支，见 [关卡设计.md](关卡设计.md) §7.2c。

> 这两次修改有同一个模式：**指标一旦真的拿去跑，就会暴露它到底可不可计算。** 写在文档里看着都挺像样，跑一遍才知道哪条是判据、哪条只是愿望。

**「关卡非平凡」不适用于对照关。** 韩国书院没有任何正向交互，最优布局退化为最大独立集，贪心在这类问题上结构性地不可能失败——这是数据决定的，不是关卡没做好。对照关因此换用「文明有差异」那条判据，见 [关卡设计.md](关卡设计.md) §1.2。
