## 1. 设计目的

### 1.1 目标体验：看懂，而不是赢

自由模式没有胜负条件。它要回答的问题是：**「文明 6 的区域相邻加成到底怎么运作？」**

玩家在这里做的事是提问与验证：把学院放在两座山之间会怎样？挪开一格会损失多少？德国的汉萨和普通工业区差在哪？每一个问题都由拆解面板当场回答。

### 1.2 为什么它必须先于挑战模式存在

挑战模式要求玩家做优化，而优化的前提是理解规则。一个不理解相邻加成的玩家在残局里只能乱试。**自由模式是挑战模式的教学层**，也是本作最接近"工具"的部分——它对文明 6 老玩家有独立价值：一个可以随便摆的相邻加成计算器。

### 1.3 自由模式就是关卡编辑器 ⭐

自由模式里玩家能做的全部操作（布置地块、放区域、建建筑、设文明与科技阶段），正好等于定义一个残局所需的全部信息。

因此**不另做关卡编辑器**：自由模式加一个「导出为关卡」就是编辑器。这省掉一整套工具的开发，并使关卡制作与游戏本体共用同一套校验——关卡不可能配出自由模式里摆不出来的非法局面。

## 2. 玩家侧流程

```
进入自由模式
   ↓
选文明 / 领袖 ──► 立即应用替换关系（如德国 → 汉萨替换工业区）
   ↓
设科技阶段（见 §3.4）
   ↓
┌─► 观察地图（地形/地貌/资源全部可见）
│      ↓
│  从候选列表选一个区域或建筑
│      ↓
│  悬停任意格 ──► 浮层：放这里产出变成多少、差额多少、哪几条规则贡献
│      ↓
│  放置（合法性不满足的格子已置灰并标原因）
│      ↓
│  拆解面板整树刷新
│      ↓
│  展开任一节点下钻到规则 id
│      ↓
└──┴ 撤销 / 改地块 / 换文明 / 换科技阶段 → 回到观察

任意时刻：导出当前局面为关卡
```

## 3. 规则定义

### 3.1 可编辑的内容

| 对象 | 可否编辑 | 说明 |
|---|---|---|
| 地块的地形 / 地貌 / 资源 | ✅ | 自由模式需要能构造任意地形组合以验证规则 |
| 区域 | ✅ 放置与移除 | 受合法性校验约束 |
| 建筑 | ✅ | 受所属区域与前置约束 |
| 文明 / 领袖 | ✅ 随时可换 | 换后重新解析替换关系并重新求值 |
| 科技 / 市政解锁集合 | ✅ | 见 §3.4 |
| 城市中心位置与人口 | ✅ | 决定工作范围与区域数上限 |

### 3.2 放置与移除

- 合法性校验完全委托求值器侧的规则（见 [SDD-局面求值器.md](SDD-局面求值器.md) §5）
- 不可放置的格子**置灰并显示原因**，不做「可点但报错」
- 移除无代价、无冷却。自由模式不模拟建造成本的时间维度
- **撤销栈**：至少支持多步撤销。因为求值器无历史状态（不变量 I3），撤销只需回退局面并重新求值，不需要反向计算

### 3.3 拆解面板的层级

固定四层，不可折叠为三层：

```
产出类型  →  来源实体  →  单条规则  →  规则 id 与计数
（科技）     （学院@2,-1）  （相邻山脉×2）   [adjacency_rules:R-xxxx]
```

要求：
- 增量为 0 的规则**灰显但保留**（求值器边界 E1）
- 前置未满足的规则灰显并标注所缺前置（边界 E14）
- 任一层级的和必须等于上层值，界面上不出现「其他」项（不变量 I4）

### 3.4 科技阶段的呈现：不做

**本节原先的前提是错的。** 它写着"相邻规则带前置科技与市政，所以自由模式必须让玩家控制这两个集合"——但区域侧 **103 条相邻规则里 0 条带前置科技**（见 §10 D1 的核实）。前置只出现在建筑与改良设施上，而改良设施本期不做。

所以**不做科技阶段控件**：默认全解锁。原先那条"界面必须始终显示当前科技阶段，否则玩家会把'规则没生效'误认为'规则不存在'"的顾虑在这里不成立——没有任何区域侧规则会因科技而不生效。

求值器的 `已解锁科技` 接口保留（建筑侧要用，边界 E14 的灰显逻辑也留着），只是自由模式不暴露开关。

### 3.5 导出为关卡

导出内容 = 完整局面 + 一个待填的目标与约束。导出格式即关卡配置表的行格式（见 [SDD-挑战模式.md](SDD-挑战模式.md) §4），使导出结果可直接作为关卡草稿。

## 4. 数据结构

本模式不新增规则表，只新增会话态（不落配置表）：

| 项 | 内容 |
|---|---|
| 当前局面 | 求值器的 boardState |
| 撤销栈 | 历史局面序列 |
| 当前选中的待放对象 | 区域 id 或建筑 id |
| 面板展开状态 | 纯 UI 状态，不影响求值 |

## 5. 状态机

```
        ┌──────────┐  选中区域/建筑   ┌──────────┐
        │  Idle    │ ───────────────►│ Selected │
        │ 无选中    │◄─────────────── │ 待放置    │
        └────┬─────┘   取消/放置完成   └────┬─────┘
             │                             │ 悬停某格
             │ 点击已有区域                  ▼
             │                        ┌──────────┐
             │                        │Previewing│ 求值假设局面
             │                        │ 显示浮层  │
             │                        └────┬─────┘
             │                             │ 点击合法格
             ▼                             ▼
        ┌──────────┐              ┌────────────────┐
        │Inspecting│              │ 写回局面 → 重求值 │
        │ 查看拆解  │              └────────────────┘
        └──────────┘
```

`Previewing` 状态下**只读求值**，绝不写回局面——这是预览与放置结果一致的保证。

## 6. 边界情况

| # | 情况 | 处理 |
|---|---|---|
| F1 | 换文明后，已放置的特色区域在新文明下不存在 | **待定 → 建议：转为被替换的基础区域并提示**。直接删除会让玩家丢失布局，静默保留会产生非法局面 |
| F2 | 降低科技阶段后，已放置区域的前置不再满足 | 区域保留，相关加成灰显并标注所缺前置。自由模式不因此判非法 |
| F3 | 修改地块地形，导致其上已有区域的地形要求不满足 | **待定 → 建议：拒绝该地形修改并提示**，优先保护已有布局 |
| F4 | 缩小人口导致区域数超上限 | 同 F3，拒绝修改并提示 |
| F5 | 移动城市中心导致部分区域出界 | 同 F3 |
| F6 | 撤销栈为空时点撤销 | 按钮置灰 |
| F7 | 悬停在非法格 | 不求值，浮层只显示不可放置的原因 |
| F8 | 空局面（无任何区域） | 正常求值，拆解面板显示地块基础产出 |

F1、F3–F5 是同一类问题：**编辑操作使既有局面变非法**。统一原则是**拒绝破坏性编辑并说明原因**，而不是自动修补局面——自动修补会让玩家看不懂自己的布局为什么变了。

## 7. 与其他系统的接口

| 方向 | 对象 | 数据 |
|---|---|---|
| 输出 | 求值器 | 局面（含科技市政集合） |
| 输入 | 求值器 | 产出明细树 |
| 输出 | 挑战模式 | 导出的关卡草稿 |

本模式**不写配置表**，导出功能产出的是文件草稿，由人工确认后入表。

## 8. 验收标准

- [x] 能选文明，换文明后替换关系立即生效 —— 实测换韩国后全图预览从「贴山 +1」变成「孤立 +4」，**地图本身就把「书院要分开」画出来了**。领袖选择暂未接（首期领袖不影响相邻，见立项书）
- [x] 每个合法格直接把预览差额画在图上（不用悬停一个个试）。差额由**两次求值相减**得到，与实际放置后的差额必然一致 —— 这不是靠测试保证的，是靠「渲染层不自己算」保证的
- [x] 非法格置灰 + 悬停显示原因（「该地形不可建区域」「超出城市 3 格工作范围」「已有 市中心」…），不做「可点但报错」
- [x] 四层齐全：产出类型 → 来源实体@坐标 → 单条规则 → `adjacency_rules.规则id`
- [x] 增量为 0 的规则灰显保留（学院 12 条全在）；被文明排除的规则带「被文明排除」标签。前置未满足的分支已实现，当前无数据可触发
- [x] 由求值器的 I4 保证并有自动测试；面板只是把树画出来，不做合并
- [x] 撤销栈 200 步。因为求值器无历史状态（I3），撤销只需回退局面并重新求值
- [ ] **未做，而且是有意不做**：区域侧 103 条规则里 0 条带前置科技，所以调科技不会改变任何相邻加成 —— 做一个不产生可见变化的控件反而误导。纳入改良设施相邻后再做
- [ ] 部分。放置 / 移除 / 换文明 / 撤销已覆盖，其余待逐条过
- [ ] **未做**（§3.5）

## 10. 待决策清单

**✅ D1 · 科技阶段的呈现方式 —— 已解除（2026-09-25）**
定为**默认全解锁，不做任何科技阶段控件**。

原先的三个方案（全解锁开关 / 阶段选择器 / 自定义勾选）都假设"科技阶段会影响相邻产出"。**这个假设在数据上不成立**：区域侧 103 条相邻规则里 **0 条带前置科技**（`adjacency_rules.csv` 的 `前置科技` 列全为「无」）。带前置的是**建筑**与**改良设施**，而改良设施按 D7 本期不做。

所以任何科技控件都会是一个**拖动它什么都不变的控件**——那不是功能缺失，是误导。求值器仍然读 `已解锁科技` 集合（接口留着，建筑侧要用），只是自由模式不暴露它。

> 这条值得记的地方在于：**它不是在三个方案里挑了一个，而是发现问题本身问错了。** 先去数了一遍数据，才知道这个决策点根本不存在。

**D2 · 布局的保存与分享**（是否需要持久化，或仅导出为关卡草稿即足够）

**D3 · 地块编辑的粒度**（是否允许编辑河流与自然奇观，它们的相邻语义与地形不同）
